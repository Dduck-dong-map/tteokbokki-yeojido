# 떡볶여지도 기술 스택

2026-10-28 · 기획안 v4 9절의 근거 문서. MVP 기능 범위는 기획안 5절, 제품 결정은 기획안 13절에 있다.

## 1. 결정 요약

**확정**

- 프레임워크: Next.js 16.4 App Router + TypeScript + Tailwind v4 + shadcn/ui, 패키지 매니저 pnpm (초기 세팅 완료)
- 캐싱: Cache Components 켬(공식 권장 기본값). 데이터는 기본이 동적이고, 캐시는 필요한 곳에만 `"use cache"`로 둔다
- 지도: 네이버 지도 JS v3 + 커스텀 스타일. `MapView` 인터페이스 뒤에 두어 MapLibre로 교체 가능하게 한다
- DB: Supabase(Postgres + PostGIS)
- 쓰기 경로: 서버(route handler)만 쓰고, DB의 RLS는 읽기 전용
- 구조: 모듈형 모놀리스(앱 하나, 기능별 폴더)
- 호스팅: Vercel(베타는 Hobby, 공개 출시 때 Pro)
- 에이전트 지침: 루트 `AGENTS.md` 하나(Next.js 관리 블록)

- 관리자 로그인: 관리자만 Supabase Auth 매직 링크 + `admins` 테이블

**확정 전(6절 추천안)**: 도배 방지 한도, 조회·캐시·적재 방식 등 10가지

## 3. 아키텍처

```
[브라우저 / PWA]
   │  지도·조회: Supabase anon 키, RLS로 승인된 가게만 SELECT
   │  제보·확인·신고: Turnstile 토큰과 함께 route handler로
   ▼
Next.js 16.4 (App Router) ── Vercel
   ├ 지도 홈·필터·상세·제보 폼        (클라이언트, MapView 뒤에 네이버 지도)
   ├ /[지역]/[취향] 목록              (서버 렌더, "use cache" + cacheLife/cacheTag)
   ├ /admin 승인 화면                 (같은 앱, 관리자 로그인, 서버에서 권한 재검사)
   └ route handlers                   (Turnstile 검증, 기기·IP 한도, 입력 검증, service role INSERT)
   ▼
Supabase: Postgres + PostGIS (RLS, 마이그레이션 SQL)
```

- **모듈형 모놀리스**: `places / reports / geo / moderation` 폴더로만 나누고 서비스는 쪼개지 않는다. 1인 운영, 월 3만 명, 쓰기 하루 수십 건 규모에서는 분리 비용이 이득보다 크다.

### 쓰기 경로 보안

로그인 없이 누구나 가게를 올리는 서비스라 보안 경계를 서버에 둔다.

- 브라우저 → route handler(또는 Server Action) → service role로만 INSERT. anon 키는 RLS로 승인된 가게 SELECT만 허용한다.
- DB 연결 문자열(RLS를 거치지 않음), service role 키, Turnstile 비밀 키는 Vercel 환경 변수에만 두고, 이 키를 쓰는 모듈에는 `import "server-only"`를 넣어 클라이언트 번들에 들어가지 않게 한다. 클라이언트에 노출하는 값만 `NEXT_PUBLIC_`.
- Turnstile 검증은 서버에서만 가능하므로 DB 함수만으로 쓰기를 처리하지 않는다.
- 도배 방지는 다층으로 한다: Turnstile + 기기 하루 10건 + IP는 넓게. 캠퍼스 와이파이 하나에 수백 명이 붙을 수 있어 IP를 빡빡하게 걸면 정상 제보자가 막힌다. 새 가게는 운영자 승인 후 반영되므로 스팸이 지도에 바로 나오지 않는다.
- **기기 식별 방법은 미정**이다(6절 남은 결정). 정해지기 전까지 한도는 Turnstile·IP 기준으로 설계한다.
- **한도 카운터는 원자적으로**: "조회 후 증가"는 동시 요청에 뚫리므로, 하루 단위 카운터를 Postgres 함수 하나에서 증가와 한도 비교를 함께 처리한다(UPSERT). 오래된 행은 주기적으로 지운다.
- **Turnstile 검증**: 서버에서 siteverify로 검증하고 hostname·action이 우리 것인지 확인한다. 검증 실패나 타임아웃이면 제보를 받지 않고(실패 시 차단) "다시 시도해 주세요"를 보여 준다. 순서는 Turnstile → 기기·IP 한도 → 입력 검증 → INSERT.
- **요청 방어**: route handler는 `Origin` 헤더가 우리 도메인인지 확인하고 본문 크기를 제한한다(Server Action은 Next.js가 Origin을 확인한다). 환경 변수는 시작 시 스키마로 검증해 빠진 키가 있으면 바로 실패하게 한다.
- **기록**: 제보 행에 기기 ID와 IP 해시를 남겨 도배 추적과 일괄 삭제에 쓴다. 서버 오류는 Sentry로 모은다. service role 키가 새면 모든 쓰기가 가능해지므로, 유출이 의심되면 Supabase에서 키를 즉시 교체한다.

### 관리자 승인과 캐시 갱신

- **관리자 로그인**(2026-10-28 확정): 관리자만 Supabase Auth 이메일 로그인(매직 링크)을 쓰고, 관리자 목록 테이블로 권한을 확인한다. `proxy.ts`는 `/admin`의 낙관적 확인만 하고, 승인 Server Action마다 서버에서 권한을 다시 검사한다. 일반 사용자 로그인(카카오)은 2차 그대로다.
- **승인 → 화면 반영**: 승인 Server Action이 DB를 바꾼 뒤 해당 가게의 지역·취향 캐시 태그를 `revalidateTag(tag, 'max')`로 무효화한다. 관리자 화면 자체는 `updateTag`로 바로 갱신한다. 태그 이름은 `places:<지역>` 형태로 통일한다.
- **조회 경로**: 지도 홈은 브라우저에서 supabase-js(anon 키)로 화면 영역 조회 함수(RPC)를 부른다. 캐시를 거치지 않으므로 승인 즉시 지도에 보인다. 목록 페이지만 서버에서 `"use cache"`로 캐시하며, 캐시 키는 함수 인자(지역, 취향)로 자동으로 정해진다. 목록 페이지가 최대 몇 시간 늦게 반영되는 것은 허용하되, 승인 때 태그 무효화로 바로 갱신한다.
- **'아직 있어요'**: 브라우저가 보낸 좌표와 가게 좌표의 거리를 서버가 PostGIS로 다시 계산해 기준 거리 안일 때만 마지막 확인일을 갱신한다. 좌표 위조는 막을 수 없으므로 기기 ID당 하루 한도로 피해를 줄이고, 그 이상은 수용한다.

## 5. 테스트와 성능

**테스트 계획**

| 대상 | 종류 | 핵심 케이스 |
| --- | --- | --- |
| 필터 → 쿼리 | 단위 | 태그 조합, 0건, 맵기 경계값 1·5 |
| 제보 route handler | 단위 + 통합 | Turnstile 실패, 기기 한도 초과, 잘못된 태그, 같은 제보 3건 |
| RLS | DB 테스트 | anon이 INSERT·UPDATE 불가, 미승인 가게 미노출 |
| '아직 있어요' | 통합 | 먼 위치 거절, 연속 클릭, 위치 권한 없음 |
| 핵심 흐름 | Playwright(E2E) | 필터 → 상세 → 길찾기, 제보 제출 → 관리자 승인 → 지도 반영, 위치 거절 → 서울시청 |
| 목록 페이지 | 통합 | 빈 지역, 존재하지 않는 취향 주소(404), 캐시 재생성 후 새 가게 반영 |
| 관리자 권한 | 통합 | 비로그인·관리자 아닌 계정으로 승인 Server Action 직접 호출 시 거절 |
| 기기·IP 한도 | 통합 | 한도 초과 제보 거절, 동시 요청에도 한도를 넘지 않음(기기 식별 방법이 정해지면 케이스 추가) |
| 승인 → 캐시 | E2E | 승인 직후 해당 지역 목록 페이지에 새 가게가 보임 |

**성능**

- 지도 화면 영역(bbox) 쿼리 + GIST 인덱스, 화면당 핀 300개 상한. 묶음(클러스터)은 MVP에서 클라이언트(supercluster)로 처리한다.
- 서버 코드(route handler, Server Action, `"use cache"` 함수)는 Supabase **연결 풀러(트랜잭션 모드)를 거쳐 Postgres에 직접 연결**한다(2026-10-28 확정). 풀러 없이 바로 연결하면 서버리스 요청마다 연결이 늘어 한도에 닿는다. 브라우저의 지도 조회만 supabase-js(anon 키, RLS)를 쓴다.
- 필터 개수 함수는 디바운스. 네이버 지도 스크립트는 지연 로드, 목록 페이지는 지도 없이 렌더.
- 이미지·폰트는 `next/image`, `next/font`로 최적화하고 폰트는 서브셋으로 자체 호스팅.
