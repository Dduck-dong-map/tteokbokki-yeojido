# MVP · 거지맵 구도 추리기 (2026-11-04)

사용자 요청: 「거지맵의 서비스 구도를 추려서 여기 맞춰서 MVP 제작하자」
보드: `docs/design/index.html` → 위 「MVP」 버튼(MV-00 표, F6·F7 흐름) · 웹: `localhost:3100`

## 결론

거지맵의 뼈대는 **「모두가 고치는 지도」** 다. 찾기 → 제보 → 검증 → 갱신 네 칸이 돌아야 지도가 살아 있다.
떡볶여지도는 화면은 대부분 있었지만 **저장이 하나도 안 돼서 이 고리가 돌지 않았다.** 이번 MVP는 이 고리를 실제로 돌게 만든 것이다.

## 거지맵에서 확인한 것 (11-04 웹에서 직접 둘러봄)

제보·평가·신고는 눌러 보지 않았다(읽기만). 앱 전용 기능은 앱스토어 설명 기준.

| 칸 | 거지맵 |
|---|---|
| 찾기 | 지도 + 주변 가게 목록(가까운순). 핀에 대표 가격·별점. 필터: 조회 대상·가격 슬라이더·음식 종류. 「이 지역 더 보기」 |
| 상세 | 사진 · 카테고리 · 저장 · 메뉴·가격 · 제보일 · 영업시간 · 메모 · 태그 · 작은 지도 · 네이버 지도로 · 종합 평점 + 맛·양·값·위생 · 댓글(비회원은 닉네임+비밀번호). 더보기: 변경 이력 · 정보 수정 · 신고 · 공유 · 가게 차단 |
| 제보 | 비회원 가능(자동 닉네임) · 상호 검색(네이버) · 카테고리 1~3 · 메뉴·가격(5개까지) · 태그 · 영업시간 · 메모 · 사진 2장 이상. 식당 외에 공간·혜택 제보도 있음 |
| 검증 | 사전 검증 없이 올리고 뒤에서 거른다. 심판대 = 등록 1주 이내 가게(「아직 정보 검증이 필요해요」). 투표·신고로 노출 제한 |
| 갱신 | 가게 업데이트 = 사진 없거나 오래된 가게 목록 + 포인트 보상. 누구나 정보 수정 |
| 그 밖 | 거지방(커뮤니티) · 쿠폰 장터 · 핫딜 · 쇼핑 적립 · 포인트(출석·만보기·퀴즈) · 지도 순위. 팝업과 전면 광고 많음 |
| 검색 유입 | `/restaurants/seoul`: 25개 구 · 가격별 · 메뉴별 |

## 무엇을 가져오고 뺐나

구도만 가져오고 이름·문구·모양은 우리 것으로 했다.

**가져옴**
- 지도 + 주변 목록, 핀(도장) 밑 가격·별점 (14.5배부터)
- 승인 없이 바로 올라가는 제보 + 일주일 「확인 중」
- 맞아요·달라요, 신고로 걸러 내기
- 누구나 고치기 + 변경 이력
- 오래됐거나 비어 있는 가게 목록 → 「함께 고치기」 탭 하나로 묶음

**줄임**
- 별점 네 항목 → 별 + 맵기 두 축 (팀 결정 10-28)
- 댓글 + 평가 → 「평가 + 한 줄 후기」 하나로 합침
- 사진 2장 → 1장 (`MIN_PHOTOS` 값만 바꾸면 2장)

**뺌**
- 커뮤니티 · 쿠폰 · 핫딜 · 쇼핑 적립 · 포인트 · 순위 · 회원 가입 · 팝업·전면 광고
- 이유: 1차는 지도 고리에 집중. 거지맵 앱 리뷰의 불만도 전면 광고에 몰려 있다.

## 이전 기획과 달라진 결정

| 항목 | 전 | 지금 |
|---|---|---|
| 제보 반영 | 운영자 승인 후 | **바로 올라감, 뒤에서 거름** (어드민기획_v1 승인함과 다름) |
| 정보 수정 | 다른 2명 동의 후 | **바로 반영 + 이력** |
| 한 줄 후기 | 2차 | **1차** |
| 제보 사진 | 선택 | **1장 이상 필수** |
| 제보 가격 | 건너뛰기 가능 | **대표 메뉴 가격 필수** (지도에 나옴) |
| 아래 메뉴 | 3개 | **4개** (함께 고치기) |

팀 결정인 첫 칸 정보 순서(이름 → 위치 → 종류 → 맵기 → 가격 → 길찾기)는 그대로 뒀다. 그 아래로 내용을 이었다.

## 규칙 값 (`web/src/lib/wiki.ts` 한 곳에서 바꿈)

| 값 | 지금 |
|---|---|
| 확인 중 기간 | 7일 |
| 확인 끝 | 맞아요 3명 |
| 지도에서 내림 | 달라요 3명 또는 신고 3명 (신고 대부분이 폐업이면 「문 닫음」) |
| 후기 숨김 | 신고 3명 |
| 중복 안내 | 80m 안 같은 이름 |
| 제보·수정 제한 | 기기·접속 위치 기준 하루 10건 |
| 한 표 기준 | 같은 기기 또는 같은 접속 위치는 가게마다 한 표 |
| 「확인이 필요해요」 | 사진 없음 · 영업시간 없음 · 60일 넘게 확인 안 됨 |

숫자는 가정치다. 같은 와이파이의 두 사람은 한 표로 묶이므로 학교·카페 앞 가게는 3명 모으기가 어려울 수 있다. 베타에서 봐야 한다.

## 개인정보 쪽 선택

- 로그인 없음. 기기 표시·접속 위치는 해시로만 저장하고 화면에 내보내지 않는다.
- 「아직 있어요」 거리는 기기 안에서 재고 위치를 서버로 보내지 않는다 (위치기반서비스 신고 쟁점을 피함, 로드맵 M2-05). 대신 속이려면 속일 수 있다.
- 사진은 줄여서 다시 만들어 올린다 → 찍은 위치(EXIF)가 지워진다.

## 아직 안 된 것 (출시 전 필수)

1. **저장소**: 지금은 서버 파일 하나. Vercel 에서는 오래 남지 않는다 → **Supabase 키 필요 (사용자·팀원)**. 받으면 `db.ts` 안만 바꾼다. DB 설계 SQL 도 이번 구조(후기·이력·투표·신고)에 맞춰 고쳐야 한다.
2. **실제 가게 자료**: 지금 예시 16곳. 첫 300곳은 직접 넣어야 지도가 비어 보이지 않는다.
3. **운영자 화면**: `/admin` 은 아직 시안. 내려간 가게를 되돌리려면 파일을 직접 고쳐야 한다.
4. **주소 검색**: 도로명주소 키 전이라 직접 입력. 구·동은 글자에서 뽑는다 (마포·서대문 외에는 지역 페이지에 안 나옴).
5. **운영 정책**: 익명 사진·후기, 가게 이름이 걸린 비방, 약관·개인정보 안내.
6. **휴대폰 실기 시험**: 사진 찍어 올리기, 지도 핀 맞추기, 속도.
7. **스팸 방어**: 접속 위치를 바꾸면 표를 늘릴 수 있다. 공개 전에 더 봐야 한다.

- 조선100년체의 사용 금지는 눈누 표 기준이다. 공식 페이지(event.chosun.com/100/100font.html)는 도구로 열리지 않아 원문을 못 봤다. 로고로 쓰고 싶으면 방일영문화재단에 문의해야 한다. 사진 속 글자를 잘라 로고로 쓰는 것도 같은 문제다.
