# 떡볶여지도 MVP PRD

2026-10-28 · 근거 문서: [기획안 v4](기획안_v4_2026-10-26.md)(5·6·7·13절), [기술 스택 v1](기술스택_v1_2026-10-28.md), [화면 시안 v2](화면시안_v2_2026-10-26/README.md), `package.json`

> 기획안 6절(화면 흐름)과 5절(MVP 범위)이 다른 곳은 **5절을 따른다**(13절 "MVP 기능 범위: 5절" 확정). 그래서 필터 시트의 1인분 가격·영업 중·혼밥, 제보 사진 첨부, 한 줄 후기, 맛 태그 투표는 이 문서에 없다.

## 🎯 핵심 정보

**목적**: 내가 좋아하는 떡(밀떡·쌀떡)·스타일·맵기의 떡볶이를 파는 가게를 지도에서 바로 골라내지 못하는 문제를 푼다.
**사용자**: 주말마다 떡볶이집을 찾아다니며 기록하고 제보하는 20~30대 떡볶이 애호가(1차), 그리고 마포·서대문에서 근처 분식집을 찾는 학생·직장인.

## 🚶 사용자 여정

```
1. 지도 홈 (모든 입구의 도착점, 가입 없음)
   ↓ 첫 방문: 위치 권한 요청

   [허용] → 내 위치 중심 지도
   [거절] → 서울시청 중심 지도 (지도 홈에 그대로 머묾)
   ↓

2. 지도 홈에서 취향 필터 선택 (떡 · 스타일 · 맵기)
   ↓ 고를 때마다 "조건에 맞는 가게 N곳" 표시, 지도 핀이 바로 걸러짐

   [핀 누름] → 아래에서 가게 미리보기 카드가 올라옴
               ↓ 옆으로 밀기 → 가까운 다음 가게 카드
               ↓ 카드 누름
3. 가게 상세
   ↓ 사용자 선택 분기

   [길찾기]        → 네이버 지도 앱 / 카카오맵 앱으로 이동 (여정의 끝점)
   [아직 있어요]   → 가게 근처면 마지막 확인일 갱신, 아니면 "가게 근처에서 눌러 주세요"
   [정보가 달라요] → 제보하기 (정보 수정·폐업 신고, 가게 미리 선택됨)

4. 제보하기 (지도 홈의 떠 있는 제보 버튼 또는 가게 상세에서 진입)
   ↓ 제보 종류 → 가게 선택/입력 → 떡·스타일·맵기 → 대표 메뉴 가격 → 제출
   ↓
   완료 화면 "승인되면 지도에 올라가요" → [지도로 돌아가기] → 지도 홈

검색 유입: 검색엔진 → 지역·취향 목록 → 가게 상세 → (3번과 같음)
목록 탭:   목록 모아보기 → 지역·취향 목록 → 가게 상세

운영자: 관리자 로그인 → 제보 승인 ⇄ 가게 관리

※ 실패·빈 상태
- 필터 결과 0곳 → 지도에 핀 없음 + "조건에 맞는 가게가 없어요" 띠 + [필터 초기화] 버튼
- 지도 화면 안에 가게 0곳(필터 없음) → "이 근처는 아직 비어 있어요" + [제보하기] 버튼
- 지역·취향 목록이 0곳 → "아직 등록된 가게가 없어요" + 같은 지역 전체 목록 링크 + [제보하기]
- 없는 지역·취향 조합 주소 → 찾을 수 없음 화면 + [목록 모아보기]
- 아직 있어요: 위치 권한 거절 → "위치를 허용해야 확인할 수 있어요" 안내, 가게 상세에 머묾
- 제보 제출 실패(사람 확인 실패·네트워크) → 입력 내용 유지, "다시 시도해 주세요"
- 제보 하루 한도 초과 → "오늘은 제보를 더 받을 수 없어요. 내일 다시 부탁드려요", 지도 홈으로
- 폐업 승인된 가게의 상세 링크 → "문을 닫은 가게예요" 표시 + [근처 다른 가게 보기](지도 홈)
- 관리자 페이지에 관리자 아닌 사람이 접근 → 관리자 로그인으로 이동
- 지도 불러오기 실패 → "지도를 불러오지 못했어요" + [목록으로 보기](목록 모아보기)
```

### 3. MVP 이후 기능 (제외)

- 1인분 가격대·영업 중·혼밥 필터 — 300곳 모두의 가격·영업시간을 처음부터 채우기 어려움. 가격은 상세에 표시만
- 제보 사진 첨부 — 저장 비용과 사진 검수 부담
- 가격·맵기 변경 "2명 동의" 자동 반영, 맵기 투표 평균 — 초기엔 제보가 적어 동의가 모이지 않음
- 같은 제보 3건 우선 검토(승인 순서 자동 정렬) — 제보가 하루 수백 건이 될 때
- 최근 7일 제보 수 첫 화면 공개 — 제보가 적을 때 빈 서비스처럼 보임
- 365일 지난 가게 목록 자동 제외 — 출시 6개월 뒤에야 의미가 있음
- 확대하면 네이버 실제 지도로 넘어가는 화면(화면 시안 v2 제안) — 사용자 확인 전, MVP 지도는 바탕 색·선만 맞춤
- 다크 모드, 떡지순례 도장, 한 줄 후기·맛 투표, 내 떡볶이 지도, 떡볶이방, 사장님 센터, 일반 사용자 로그인 — 2차 이후(기획안 5절)

## ❓ 열린 질문과 가정

- **질문 1**: 스타일 필터 6종(기획안 5절)에 **'촉촉(일반)'과 '궁중'이 없다.** 태그 체계(7절)에는 있어서 가게에는 붙지만, 가장 흔한 일반 떡볶이를 필터로 고를 수 없다. 필터를 8종으로 늘릴까? (이 문서는 5절대로 6종으로 썼다)
- **질문 2**: 떡 필터는 4종(5절), 태그는 7종(7절: 눈사람떡·치즈떡·분모자 추가)이다. 나머지 3종은 상세에만 보이고 필터에는 없는 것으로 썼다. 이대로 괜찮은가?
- **질문 3**: '아직 있어요'를 누를 수 있는 거리를 **200m로 가정**했다. 기획안에는 "가게 근처"만 있다.
- **가정**: 첫 출시 지역은 13절 추천대로 **마포구·서대문구**, 목록 페이지는 구 단위. 서비스 범위는 **떡볶이만**(13절 결정 1 추천안).
- **가정**: 초기 크루 10명도 관리자 목록에 넣어 가게 관리로 태그를 채운다(별도 크루 화면 없음).
- **가정**: 맵기는 가게당 값 하나(운영자 입력 또는 승인된 제보). 투표 평균은 2차.
- **가정**: 같은 사람 판정('아직 있어요' 하루 1번, 제보 하루 한도)은 기술 스택 문서에서 미정인 기기 식별 방법을 따른다. 정해지기 전까지는 같은 사람을 구별하지 못하는 경우가 있다.
- **참고**: 페이지 9개로 A4 2~3쪽 분량을 넘는다. 관리자 페이지 3개를 빼면 사용자 페이지는 6개다. 줄이려면 '목록 모아보기'를 지역·취향 목록 안의 구 선택으로 합치는 방법이 있다.
