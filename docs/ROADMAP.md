# 떡볶여지도 MVP 개발 로드맵

떡·스타일·맵기 취향으로 실제 떡볶이 가게를 지도에서 골라 길찾기까지 가게 하고, 가입 없이 누구나 올리고 고치는 「모두가 고치는 지도」를 청년부(3청) 1차 사용자에게 Vercel + Neon 으로 내놓는다. 기능 정의와 수용 기준은 [PRD](PRD.md), 배포 절차와 환경 변수는 [기술 스택](개발/기술스택_v1_2026-10-28.md) 문서에 있다. 1차 MVP 코드는 대부분 구현되어 있어 Phase 마다 끝난 일(✅)과 남은 일(`[ ]`)이 함께 있다. 예상 소요 시간은 남은 일 기준 추정치이고, 단위는 한 사람과 AI 코딩 에이전트가 함께 일하는 작업일이다.

## Phase 1: 프로젝트 초기 설정 (남은 일 없음 · 11-19 완료)

- ✅ Next.js 16.4 App Router · TypeScript · pnpm · Tailwind CSS v4 · shadcn 앱 골격
- ✅ 라우트 묶음: 사용자 화면 `(site)` 13개 · 어드민 `admin` 10개 · `api` route handler 8개
- ✅ 디자인 토큰 파이프라인(`tokens.json` → `pnpm tokens` → `tokens.css` → `globals.css`)
- ✅ 로컬 DB(도커 Postgres 16 + PostGIS)와 표 SQL `db/init/001~004`(표 13개 · RLS 켬). 도커 DB 는 Phase 5 에서 지웠고 표 SQL 은 그대로 쓴다
- ✅ 시험 도구: Vitest 단위 시험, Playwright E2E(폭 390 · 768 · 1280, 파일 저장소 모드)
- ✅ 환경 변수 설명 `.env.example`, 도커 앱 서버(`pnpm app:up`, Phase 5 에서 지움)
- ✅ CI 워크플로 `ci.yml` 작성: `check`(typecheck · lint · 단위 시험) · `postgres`(표 적용 · PG 시험)
- ✅ `ci.yml` 을 깃허브에 올려 `check` · `postgres` 두 작업 통과 확인
- ✅ CI 에 E2E(Playwright) 작업 넣기
- 이유: 앱 골격 · 표 설계 · 시험 도구가 없으면 뒤 Phase 의 모듈과 화면을 올릴 자리가 없고, CI 가 돌지 않으면 뒤 Phase 의 완료 기준(시험 통과)을 푸시마다 확인할 수 없다.

**완료 기준:**
- 깃허브 Actions 에서 `check` · `postgres` 작업이 통과한다
- CI 에서 `pnpm e2e` 가 폭 390 · 768 · 1280 세 프로젝트로 돈다
- 새 Postgres DB 에 `db/init/*.sql` 을 차례로 돌리면 오류 없이 끝난다(`postgres` 작업의 표 적용 단계)

## 범위 밖

PRD 11절의 항목은 이 로드맵의 완료 조건이 아니다. MVP 이후로 둔 것은 「승인 후 공개」 스위치와 등록 검토함, 어드민 시안 화면의 실제 데이터 연결, 사진 1장 필수, 주소 · 상호 검색, 역에서 걷는 시간, 등록 단계 기록, 「같이 가요」 글의 가게 등록 잇기다. 이 가운데 이용약관 · 개인정보 처리방침, 사장님 · 권리 침해 요청 창구, 캡차 셋은 PRD 가 「공개 출시 전 필수」로 적어 Phase 5 에만 있다. 운영자 사전 승인 제보, 맵기 투표, 이용자 로그인 · 크루, 포인트 · 순위 · 쿠폰 · 광고, 떡지순례 도장 · 사장님 센터 · 배달 · 앱, 공공데이터 후보 적재는 이번에 하지 않는다.
