# 떡볶여지도 MVP 개발 로드맵

> 기준 문서: [PRD](docs/PRD.md), [기술 스택](docs/기술스택_v1_2026-10-28.md)
>
> 두 문서에 팀 배정이나 기간 추정이 없으므로 임의의 날짜 대신 선행 조건, 산출물, 완료 기준으로 계획합니다. 단계는 앞 단계 완료 기준을 만족한 뒤 진행합니다.

## 출시 목표

가입 없이 마포구·서대문구의 떡볶이 가게를 떡·스타일·맵기 취향으로 찾고, 상세 정보를 확인하고, 길찾기하거나 제보할 수 있는 MVP를 공개합니다. 승인된 가게는 지도와 검색 가능한 지역·취향 목록에 노출되고, 운영자는 제보를 검토하고 가게 정보를 관리합니다.

## 단계별 계획

### 0. 개발 기반 마무리

**상태:** Next.js 앱 초기 세팅 완료. 테스트 도구와 기능 기반은 남음.

- Vitest, Playwright, Supabase CLI 로컬 환경 설치·설정
- Supabase 클라이언트, `@supabase/ssr`, Zod, Sentry 등 필요한 의존성 구성
- 환경 변수 스키마와 서버 전용 비밀키 경계 설정
- 한글 폰트를 `next/font/local`로 적용하고 기본 템플릿 자산 정리

**완료 기준:** 팀원이 로컬 앱·DB·검증 환경을 재현할 수 있고, 필수 환경 변수 누락이 드러나며 기본 검증 명령이 통과합니다.

### 1. 데이터와 접근 제어

- `places`, `place_tags`, `menus`, `place_photos`, `reports`, `confirmations`, `devices`, `admins` 스키마와 저장소 마이그레이션 작성
- PostGIS 좌표·반경·화면 영역 쿼리와 인덱스 구성
- 공개 가게 읽기 정책과 쓰기 권한 경계 설정: 브라우저는 승인 가게 읽기만, 변경은 서버 경유
- 관리자 권한 테이블과 서버 측 권한 검사 기반 마련
- 제보 한도 카운터를 원자적으로 처리할 DB 함수 설계

**완료 기준:** 마이그레이션으로 DB를 재구성할 수 있고, 미승인 가게는 공개 조회되지 않으며 anon 사용자의 직접 쓰기가 거부됩니다.

### 2. 초기 데이터와 지도 탐색

**선행 조건:** 운영자가 네이버 클라우드 콘솔에서 Maps 신청·키·이용 조건·한도를 확인하고 스타일 시험 지도를 검토합니다.

- 인허가 공공데이터를 관리번호 기준 UPSERT로 적재하고 좌표를 보완해 마포구·서대문구 후보 약 300곳 구성
- 후보·공개·제외 상태와 중복·좌표 오류를 검수할 운영 절차 마련
- `MapView` 인터페이스 뒤에 네이버 지도 JS v3 연결, 지연 로드 및 실패 대체 경로 제공
- 지도 영역 조회, 취향 필터(떡·스타일·맵기·메뉴 포함 여부), 결과 수 표시
- URL을 필터 상태의 기준으로 삼아 새로고침·공유 링크 복원
- 맵기·등재 등급·오래된 정보가 반영된 핀과 군집, 미리보기 카드 및 가까운 가게 탐색
- 위치 권한 허용·거절, 빈 결과, 지도 로딩 실패 상태 구현

**완료 기준:** 필터와 핀이 일치하고 공유 URL이 같은 조건을 복원합니다. 위치 거절 시 서울시청 중심으로 동작하며, 조회 상한과 지도 실패 시 목록 진입을 확인합니다.

### 3. 가게 상세와 방문 전환

- 가게 상세: 주소, 운영자 사진, 메뉴·가격, 영업시간, 전체 태그, 마지막 확인일 및 오래된 정보 안내
- 네이버 지도·카카오맵 길찾기 연결 및 외부 이동 이벤트 기록
- ‘아직 있어요’ 확인: 서버에서 PostGIS 거리 재검증, 거리 밖·위치 권한 없음·당일 중복 응답 처리
- 정보 수정·폐업 제보 진입, 사장님 문의 메일 링크, 폐업 가게 안내

**완료 기준:** 지도 카드에서 상세로 이동해 정보를 확인하고 길찾기를 열 수 있습니다. 위치 확인은 서버가 거리를 재검증하며 예외 상태별 안내가 동작합니다.

### 4. 익명 제보와 운영자 승인

- 새 가게·정보 수정·폐업 신고 흐름과 입력 검증, 약관 동의, 사람 확인
- 서버 route handler에서 Turnstile 검증, 요청 출처·본문 크기 확인, 도배 방지 및 제보 저장
- 실패 시 입력을 보존하고 재시도 가능하게 처리하며 일일 한도 초과 안내
- Supabase Auth 매직 링크 관리자 로그인 및 관리자 허용 목록 확인
- 대기 제보 목록, 현재 정보와 제보 비교, 승인·반려 처리
- 승인 시 가게·태그·메뉴 반영 및 관련 지역 목록 캐시 무효화
- 관리자 가게 관리: 후보 검수, 태그·메뉴·영업시간·등재 등급·사진 편집, 공개·제외·폐업 처리

**완료 기준:** 비로그인 사용자가 제보를 제출하고, 서버 권한 검사를 통과한 관리자만 승인·반려할 수 있습니다. 승인 결과가 지도와 목록에 반영되고 미승인 내용은 공개되지 않습니다.

### 5. 지역·취향 목록과 검색 유입

- 목록 모아보기와 구 × 떡·스타일 조합 페이지 구현
- 서버 렌더링과 `"use cache"` 기반 목록 캐시, 승인 후 지역 태그 무효화
- 최근 확인 순 정렬, 조합 간 이동, 빈 목록·없는 조합 응답 구현
- 지도·카드·목록·상세 링크 간 이동 및 직접 진입 확인

**완료 기준:** 지도 없이도 구·취향별 가게를 찾을 수 있고 검색엔진이 각 목록을 읽을 수 있습니다. 존재하지 않는 조합은 찾을 수 없음 상태로 처리됩니다.

### 6. 출시 준비와 비공개 베타

- 이용약관·개인정보 처리방침·위치정보 이용 안내 및 문의 주소 게시
- GA4 기준 이벤트(필터 사용, 길찾기, 제보 제출)와 Sentry 서버 오류 수집
- 핵심 흐름, RLS, 관리자 권한, 제보 한도, 캐시 갱신, 위치 거절·빈 상태 점검
- 실제 가게 데이터와 좌표·태그·가격을 표본 검수하고 초기 300곳 준비 상태 확인
- Vercel 비공개 베타 배포, 운영자 계정·환경 변수·모니터링 확인

**완료 기준:** 핵심 사용자·관리자 흐름이 배포 환경에서 검증되고 정책 페이지·오류 수집·기준 지표가 활성화되어 초대 사용자 베타를 시작할 수 있습니다.

### 7. 공개 출시

- 네이버 지도 이용 조건·사용 한도, 도메인 및 배포 설정 최종 확인
- 공개 출시 전에 Vercel Pro로 전환
- 베타 피드백과 오류·성능·제보 처리량을 검토하고 공개 범위 확대 결정

**완료 기준:** 공개 운영에 필요한 지도·호스팅 조건과 운영 대응 절차가 확인되고 제보 승인 큐를 감당할 수 있습니다.

## 선행 결정 및 확인 항목

| 항목 | 현재 상태 | 필요한 시점 |
|---|---|---|
| 네이버 지도 신청·키·이용 조건·사용량 | 운영자 콘솔 확인 필요 | 지도 탐색 구현 전 |
| 제보/확인 중복 제한용 기기 식별 | 미정. 확정 전 Turnstile·IP 기준으로 제한 설계 | 쓰기 경로 완성 전 |

| 공개 호스팅 플랜 | 베타 Hobby → 공개 출시 Pro 계획 | 공개 출시 전 |

## MVP 범위 밖

1인분 가격·영업 중·혼밥 필터, 사용자 제보 사진, 후기·맛 태그 투표, 일반 사용자 로그인, 내 지도·커뮤니티·사장님 센터, 자동 동의 집계·우선 검토는 이 로드맵의 완료 조건이 아닙니다. 출시 후 사용량과 운영 부담을 확인한 뒤 별도 계획으로 다룹니다.

## 검증 기준

- **탐색:** 필터 조합과 결과 수·핀 일치, 공유 URL 복원, 0건 처리
- **상세·전환:** 상세 정보 표시, 길찾기 이동, 이벤트 기록
- **위치 확인:** 거리 밖 거부, 당일 중복 처리, 위치 권한 거절 안내
- **제보·보안:** Turnstile 실패, 잘못된 태그, 한도 초과, 직접 DB 쓰기 거부
- **운영:** 비관리자 승인 차단, 승인·반려 데이터 변경, 승인 후 목록 캐시 갱신
- **검색 페이지:** 빈 지역, 잘못된 조합, 캐시 이후 신규 가게 반영
- **배포:** 위치 거절→서울시청 지도, 제보→승인→지도 반영의 주요 E2E 흐름
