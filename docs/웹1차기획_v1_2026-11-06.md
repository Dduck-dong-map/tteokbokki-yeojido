## 0.5 한 장 요약

- **문제:** 화면은 모바일 폭(480px)에 고정돼 PC에서 어색하다. 가게 상세에 지도가 없다. 소개글을 쓸 곳이 없다. 어드민은 예시 데이터로만 움직이고 옛 승인 방식이다. 저장소가 임시 파일이라 공개할 수 없다.
- **해결:** 같은 주소의 반응형 웹으로 만든다. 등록에 소개글을 넣고, 상세를 N-05 기존 디자인 + 지도로 되돌리고, 맵기 투표를 빼고, 바로 공개되는 등록을 어드민이 뒤에서 통제한다.
- **핵심 지표:** 주간 길찾기 누른 방문자 수 (KPI-W01). 가드레일 = 일주일 안에 내려간 등록 비율.
- **순서:** W1 반응형·상세·등록(키 없이 가능) → W2 어드민 연결 → W3 Supabase(키 필요) → W4 실제 가게 300곳·약관·폰 시험 → W5 비공개 베타 → 공개.
- **위험:** 도배와 가게 비방, 빈 지도, 아직 안 해 본 폰 실기 시험. 어드민·캡차·첫 300곳·실기 시험으로 막는다.
- **사용자 답(11-06):** 바로 공개 + 스위치 · 소개글 선택 · 로그인 없음 · W1 시작 (5절).

## 1. 문제 정의

### 1.1 문제와 사용자

| 사용자 | 언제 | 하려는 일 | 지금 막히는 것 |
| --- | --- | --- | --- |
| 찾는 사람 · 모바일 | 동네에서, 오늘 먹으러 가는 길 | 가까운 집 찾고 바로 길찾기 | 상세에 지도가 없어 어딘지 바로 안 보인다 |
| 찾는 사람 · PC | 집·회사에서 약속 잡기 전 | 넓게 비교하고 주소·링크 공유 | 가운데 좁은 띠로만 보인다 |
| 등록하는 사람 | 맛집을 알 때, 다녀온 직후 | 내 맛집을 올리고 왜 좋은지 쓰기 | 소개글을 쓸 곳이 없다. 메모는 등록 뒤 고치기에만 있다 |
| 운영자 (사용자 본인, 나중에 1~2명) | 하루 한 번, 이동 중 폰 | 이상한 등록 내리기, 신고 처리, 되돌리기 | 어드민이 시안이라 실제로 못 한다. 파일을 직접 고쳐야 한다 |

**근거:** 코드 확인(11 파일의 페이지 틀이 `max-w-[480px]`, 상세에 지도 없음, `/admin` 이 `lib/admin/sample.ts` 예시 데이터) · 거지맵 구도 정리(11-04) · 사용자 요청. **실제 이용자 인터뷰와 사용 수치는 아직 없다.** 베타에서 확인한다.

### 1.2 가설과 지표

**가설:** 누구나 소개글까지 쉽게 등록하고, 어느 기기에서든 위치와 길찾기가 바로 보이며, 나쁜 등록은 운영자가 빨리 내리면, 가게가 늘수록 길찾기가 늘어난다.

모든 목표 숫자는 **가정치**다. 지금 값이 없으므로(출시 전) 베타 4주 수치로 다시 정한다.

| ID | 지표 | 정의 | 지금 | 베타 4주 차 목표(가정) |
| --- | --- | --- | --- | --- |
| **KPI-W01 (북극성)** | 주간 길찾기 방문자 | 네이버·카카오 길찾기를 누른 방문자 수(7일) | 없음 | 주 200명 |
| KPI-W02 | 등록 완료율 | 등록 시작 중 올리기까지 간 비율 | 없음 | 40% |
| KPI-W03 | 소개글 작성률 | 새 등록 중 소개글이 있는 비율 | 없음 | 50% |
| KPI-W04 | 상세 → 길찾기 | 상세를 연 방문 중 길찾기를 누른 비율, 모바일·PC 따로 | 없음 | 15% (기획안 v5 기준값 참고) |
| KPI-W05 | 주간 새 등록·수정 | 등록 + 정보 고치기 건수 | 없음 | 주 50건 |
| KPI-AD-01′ | 신고 처리 시간 | 신고·자동 내림부터 운영자 처리까지 중앙값 | 없음 | 24시간 이내 |
| 가드레일 G-W1 | 내려간 등록 비율 | 7일 안에 숨김·중복 처리된 등록 ÷ 새 등록 | 없음 | 10% 이하 |
| 가드레일 G-W2 | 잘못 내린 비율 | 내린 뒤 운영자가 되살린 비율 | 없음 | 5% 이하 |
| 가드레일 G-W3 | 모바일 속도 | 지도 홈·상세 LCP 2.5초, INP 200ms, CLS 0.1 (실제 폰 75% 기준) | 측정 전 | 통과 |

```
[입력]                                    [북극성]
새 등록·수정(KPI-W05) ── 가게 수·신선도 ─┐
등록 완료율(W02) · 소개글(W03) ──────────┼─→ 주간 길찾기 방문자 (KPI-W01)
상세 → 길찾기(W04, 지도 넣기·반응형) ────┘
신고 처리(AD-01′) · 내려간 비율(G-W1) ──→ 믿을 수 있는 지도 (위 세 줄을 받친다)
```

### 1.3 범위와 우선순위 (MoSCoW)

| 구분 | 기능 | 왜 | 단계 |
| --- | --- | --- | --- |

**비기능 요건**

- **지원 브라우저:** 모바일 = iOS 사파리, 안드로이드 크롬 · PC = 크롬, 엣지, 사파리, 각 최신 2판 **[실기 시험 필수, 11-04 이후 아직 안 함]**.
- **성능:** G-W3. 지도 부품은 필요할 때 불러오고, 사진은 줄여서 받는다.
- **검색:** 상세·지역 페이지는 서버에서 내용을 그린다. 실제 가게가 들어오기 전까지 검색엔진 차단. `/admin` 은 항상 차단.
- **보안:** 역할 확인은 서버와 DB(RLS)가 한다. 서버 키는 브라우저에 보내지 않는다. 입력은 모두 서버에서 다시 검사한다(`lib/wiki.ts`).
- **개인정보:** 기기·IP는 해시만. 위치는 서버로 안 보낸다. 사진은 다시 만들어 EXIF를 지운다(모두 지금 유지).
- **접근성:** 대비 AA, 키보드만으로 등록·어드민 처리, 지도 도장마다 이름.
- **중단 대비:** 지도 불러오기 실패 시 주소·길찾기는 그대로 보인다(경고창#6).

### 3.3 화면별 상세

번호마다 ① 무엇 ② 누르면 ③ 어디로 ④ 예외 ⑤ 근거 순. 와이어는 보드 WB-01·02·03·04.

#### M-W-02 가게 상세 · 위치 · 길찾기 (보드 WB-01)

1. **머리:** 맵기 도장(누르면 표정) + 이름 + 종류 배지 + ♡ 저장 + 공유. 아래에 「마포구 합정동 · 350m · 오늘 21:00까지」. 거리는 위치 허용 때만, 영업시간이 없으면 빼고 5번에 「+ 영업시간 채우기」. (REQ-W06)
2. **대표 가격:** 「쌀떡볶이 1인분 4,500원」 + 「3일 전 확인」. 맵기 줄 「맵기 3 · 신라면 정도 · 대표 메뉴 기준」. (REQ-W08)
3. **위치 지도:** 「위치」 제목 + 「지도 크게 보기」. 모바일 = 고정된 작은 지도 + 도장 + 가까운 역 표시, 누르면 → M-W-01 `?store=id` 그 가게 17배. PC = 작은 지도 없음, 옆 큰 지도. 예외: 경고창#6. (REQ-W07)
4. **주소·길찾기:** 주소 + 「주소 복사」(복사됐다고 토스트) · 「합정역에서 걸어서 약 3분」(역 자료 뒤, 1km 안일 때만, 직선 어림) · 「네이버 지도로 길찾기」(크게) + 「카카오맵」.
5. **소개글:** 없으면 「이 집 소개글 쓰기」 → M-W-04 소개글 칸. 있으면 본문 + 「처음 쓴 사람 · 고친 날 · 이력」 → M-W-05. 가려졌으면 「신고로 가려졌어요」.
6. **사진 · 메뉴판 · 가게 정보(영업·이용·같이 먹기·메모 칸은 소개글로 합침):** 지금 MVP와 같음.
7. **평가:** 별 + 한 줄 후기(맵기 없음, REQ-W08). 후기 신고.
8. **마지막 확인 · 아직 있어요 · 고치기 넷:** 지금 MVP와 같음. 잠긴 가게면 「운영자 확인 중이라 지금은 고칠 수 없어요」. (REQ-AW04)
- 상태 변형: 확인 중(맞아요·달라요 칸) / 내려감 / 문 닫음 / 오래됨 — 지금 MVP와 같음. 없는 가게 = 404 경고창#7.

#### M-W-03 가게 등록 + 소개글 (보드 WB-02)

1. **가게·위치:** 이름 · 어떻게 파나요 · 주소(주소 검색, 키 전에는 직접 입력) · 지도 핀. PC는 오른쪽 큰 지도에 핀, 모바일은 칸 안 지도. 예외: 경고창#2 중복.
2. **떡·맛:** 떡(여럿) · 스타일 · 맵기 1~5 「대표 메뉴 기준」 · 별점(선택).
3. **메뉴·가격:** 대표 메뉴 + 가격(필수, 지도에 나옴) · 더하기 5개까지 · 영업시간(선택).
4. **소개글 (새 칸):** 큰 글상자 0/500. 「어떤 떡볶이예요? 왜 추천하나요?」 · 누르면 앞말이 들어가는 칩 3개(「이 집은요」 「같이 먹으면 좋은 건」 「이럴 때 가면 좋아요」) · 아래 안내 「누구나 고칠 수 있고 이력에 남아요 · 전화번호·링크는 넣을 수 없어요」. 모바일은 「건너뛰기」. (REQ-W03)
5. **사진·닉네임:** 사진 1~5장(모바일 카메라·앨범 / PC 끌어다 놓기), 찍은 위치는 지워진다는 안내, 닉네임.
6. **올리기:** → M-W-03-01. PC는 1~5를 한 화면에 잇고 왼쪽에 진행 표시. 모바일은 다섯 단계 + 아래 고정 「다음」.
- 예외: 경고창#1 빈칸(그 칸으로 스크롤) · #3 금칙어 · #4 하루 제한 · #5 올리기 실패(입력 유지, 다시 시도) · 나가기 전 임시 저장(기기 안), 돌아오면 「이어서 쓰기」. 사진 용량 초과는 #8.

#### M-W-01 지도 홈 (보드 WB-03)

1. **모바일:** 지금 구조 유지 + 입력 16px + 아래 메뉴 넷 + 등록 버튼.
2. **PC:** 위 헤더(검색이 헤더로 올라감) + 왼쪽 패널(필터 칩 · 「현재 지도에서 찾은 가게 n곳」 · 가까운순/최근 확인순 · 목록). 줄을 누르면 지도 이동 + 상세 패널. 도장에 올리면 이름·가격.
3. **빈 상태:** 지금 문구 유지(조건 없음 → 필터 초기화, 지도 안 없음 → 모두 보기).

#### M-W-04 정보 고치기

지금 화면 + 소개글 칸 + 맵기 칸. 저장하면 바로 반영 + 이력. 잠긴 가게는 들어갈 수 없다(REQ-AW04).

#### 어드민 (보드 WB-04)

어드민 v1 문서의 3.3을 기준으로, 달라지는 곳만 적는다. 부록 B 대조표 참고.

- **M-AD-01 홈:** 오늘 할 일 = 자동으로 내려간 것 · 신고 · 새 등록 · 큰 수정. 동의 대기 삭제.
- **M-AD-02 등록 검토함:** 탭 = 새 등록 · 수정 · 내려간 것 · (스위치가 켜졌을 때) 승인 대기. 상세 = 사진 · 소개글 · 메뉴 · 지도 핀 · 경고(중복 의심 · 도배 의심 · 큰 변경) + 버튼(확인함 A · 고치기 · 내리기 R · 합치기 · 기기 차단). 키보드 J·K 유지.
- **M-AD-03 가게 목록:** 상태 거르기(올라감 · 확인 중 · 내려감 · 잠김) + 표 파일 올리기(REQ-AW09).
- **M-AD-04 가게 편집:** 소개글 칸 · 잠금 · 이력에 이용자 수정도 함께.
- **M-AD-07 신고·요청:** 대상 4종 + 권리 침해 요청 + 48시간 넘으면 빨간 표시(유지).
- **M-AD-09 설정:** 공개 방식 스위치 · 규칙 숫자 바꾸기 · 금칙어 · 차단 · 운영자.
- **M-AD-10 글·사진 관리:** 후기 · 소개글 · 사진 목록 + 숨기기 · 되살리기 + 신고 수.

### 4.1 W1 결과 (11-06)

**구현:** 반응형 틀(위 헤더 · 패널 · 3단) · 상세 N-05 + 작은 지도 · 등록 다섯 단계 + 소개글 · 임시 저장 · 맵기 투표 빼기 · 정보 고치기에 맵기·소개글 · 「제보」 → 「등록」 · `/register` · 없는 가게 화면.

**관문 W1 통과 여부**

| 기준 | 결과 |
| --- | --- |
| 폭 7개 가로 스크롤 없음 (AC-W01) | 통과 (자동 시험, 화면 9개 × 폭 7개) |
| 등록 끝까지 오류 없음 | 통과 (폰 크기로 실제 눌러 봄) |

| 화면 시험 57개 | 통과 (폰 · PC · 패널형 · 지도 실패) |

**구현 중 정한 것 (기획과 다르거나 기획에 없던 것)**

- 상세 머리에 떡·스타일 태그를 남겼다. N-05 그림에는 없지만 팀 순서의 「떡볶이 종류」라서 빼면 첫 화면 여섯 가지가 깨진다.
- 「다른 가게예요」로 중복 안내를 넘길 수 있게 서버에 `notDuplicate` 를 더했다 (흐름 2.2 그대로). 비슷한 이름을 일부러 올리는 도배는 W2 합치기로 처리한다.
- 헤더 검색은 패널형에서도 넣었다 (3.2 표 기준, WB-03 그림과 다름). 768 폭에서도 들어간다. 패널형 상세처럼 목록이 안 보일 때는 Enter 로 지도로 돌아간다.
- 지도 틀에 보내는 가게 자료에서 소개글·예전 표를 뺐다. 가게가 300곳이 돼도 모든 페이지에 소개글을 싣지 않기 위해서다.
- 저장 파일 이름 바꾸기 재시도를 늘렸다 (시험에서 읽기가 몰리면 실패). 저장소는 W3 에 바뀐다.

**W1 에서 안 한 것 (기획대로 뒤 단계):** 승인 후 공개 스위치 · 금칙어 · 신고 대상 4종 · 가게 잠금 → W2 / 주소 검색 → W3 / 역에서 몇 분 · 캡차 · 약관 → W4.

**확인 못 한 것:** 개발 서버에서 저장 요청이 세 번 500(`Unexpected end of JSON input`)으로 떨어졌다. 전부 코드를 고치거나 서버를 켠 직후였고, 그 뒤 개발 서버 13번 · 배포 방식 3번(각 75개)에서는 안 났다. 오류 기록에 앱 코드 위치가 없어 개발 서버 내부로 보지만 확정은 못 했다. 다시 나면 `lib/data/db.ts` 의 `load` 부터 본다.

**출시 준비:** 운영 수칙 · 신고 처리 기준 · 권리 침해 절차 · 비상시 Supabase 관리 화면 사용법 · 공지 문구.

## 부록 A. 나중에 할 메뉴별 맵기 구조 (이번에 안 만듦)

사용자 11-06: 「맵기 투표는 메뉴마다 맵기가 다를 수 있으니 구조를 조금 수정해야 하는데 나중에 하자.」 지금 고를 필요는 없고, 지금 결정이 나중을 막지 않게 방향만 적어 둔다.

```
지금 (1차)                         나중
Store.spice = 대표 메뉴 맵기 1~5    Store.spice = 대표 메뉴의 맵기에서 자동 계산
MenuItem = { name, price }         MenuItem = { id, name, price, spice?, spiceVotes? }
Review = 별 + 한 줄 후기            SpiceVote = { storeId, menuId, level, device }
```

- 1차에서 「대표 메뉴 기준」이라고 적는 이유: 나중에 값의 뜻이 바뀌지 않는다.
- 나중에 정할 것: 지도 도장이 대표 메뉴를 따를지 가장 매운 메뉴를 따를지 · 가게 단계 이름(「초보맛」)과 메뉴의 관계 · 메뉴 이름이 바뀌었을 때 표를 어떻게 잇는지(메뉴에 고유 번호 필요).
- 지금 쌓인 `spiceVotes` 는 지우지 않는다.
